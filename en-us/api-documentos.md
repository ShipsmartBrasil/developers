# Shipment Documents

- [Back to the language README](README.md)
- Prerequisite: [Getting Started](api-primeiros-passos.md)

## Overview
- Retrieves the documents generated by the platform and by the carrier after the shipment is processed:
  AWB (label), invoice, packing list, declaration and others.
- It also returns the **attachments** you sent when creating/updating the shipment.
- Each document comes with a `url` for download and, optionally, with the content in `base64`.
- It works for shipments created in **v1 and v2**.

## Base URL
- Production: `https://api.shipsmart.global`
- Staging: `https://hmlapi.shipsmart.com.br`
- Interactive documentation: `https://api.shipsmart.global/doc` and `https://hmlapi.shipsmart.com.br/doc`

## Authentication
```
Authorization: Bearer YOUR_TOKEN
lang: pt
```

## Usage flow
1. Create the [shipment](api-remessa-v1.md).
2. Query the [status](api-rastreio.md) until the shipment appears in the `shipped` group — that is the moment
   when the documents start to exist.
3. Query the documents by `{shipping}` or by the channel.
4. Download the file through the `url` (recommended) or decode the `base64`.

> **Before `shipped` the query may return `400 Nenhum documento encontrado com o código especificado!`.**
> That is expected: wait for the processing at the carrier.

## Endpoints

### Query documents by shipment
- **Method and route:** `GET /v1/shipping/{shipping}/docs`

### Query documents by channel
- **Method and route:** `GET /v1/shipping/docs/{channel_identifier_number}/{channel_code}`
- Useful when you only stored your own order number.

## Parameters

| Name | Location | Type | Required | Default | Description |
|---|---|---|---|---|---|
| `shipping` | path | string | **yes** | - | Quotation UUID, AWB number (last 90 days) or NF-e key (44 digits) |
| `channel_identifier_number` | path | string | **yes** (by-channel variant) | - | Commercial identifier informed in the quotation |
| `channel_code` | path | integer | no | - | Sales channel code |
| `attachments` | query | boolean | no | `true` | Include the attachments you sent |
| `embedded` | query | boolean | no | `true` | Include embedded documents (AWB + invoice consolidated into a single file). Requires a specific permission |
| `base64` | query | boolean | no | `true` | Include the file content in Base64, in addition to the `url` |
| `documents` | query | string | no | all | Comma-separated list of types. When empty or absent, it returns all of them |

> **Performance tip:** send `base64=false` when you are going to download through the `url`. The payload gets much smaller
> and the response much faster.

## Filterable document types (`documents`)

| Value in `documents` | Key in `data.docs` | Content |
|---|---|---|
| `awb_pdf` | `AWB` | Label/AWB in PDF |
| `awb_zpl` | `AWB_ZPL` | Label/AWB in ZPL (thermal printer) |
| `awb_prc_pdf` | `AWB PRC` | AWB of the return/partner process in PDF |
| `awb_prc_zpl` | `AWB PRC ZPL` | AWB of the return/partner process in ZPL |
| `awb_prc_fedex_pdf` | `AWB PRC Fedex` | FedEx AWB of the return/partner process in PDF |
| `awb_prc_fedex_zpl` | `AWB PRC Fedex ZPL` | FedEx AWB of the return/partner process in ZPL |
| `invoice_pdf` | `Invoice` | Commercial Invoice in PDF |
| `packing_list_pdf` | `Packing List` | Packing list in PDF |
| `declaration_pdf` | `Declaration` | Content declaration in PDF |
| `non_dangerous_pdf` | `Non-Dangerous Object` | Non-dangerous goods declaration in PDF |

Filter example:
```
?documents=invoice_pdf,awb_pdf,awb_zpl
```

> Not every document exists in every shipment: the set depends on the carrier, the destination country and the
> type of object. Only the documents actually generated appear in `data.docs`.

## Request example

```bash
curl --request GET \
  --url 'https://api.shipsmart.global/v1/shipping/9c06fd75-d5f4-40eb-a1a8-f12086f49944/docs?attachments=true&embedded=false&base64=false&documents=invoice_pdf,awb_pdf' \
  --header 'Authorization: Bearer YOUR_TOKEN' \
  --header 'lang: pt'
```

By channel:
```bash
curl --request GET \
  --url 'https://api.shipsmart.global/v1/shipping/docs/PED-2026-0001/1?base64=false' \
  --header 'Authorization: Bearer YOUR_TOKEN' \
  --header 'lang: pt'
```

### Response fields

| Field | Type | Description |
|---|---|---|
| `data.carrier` | string | Name of the carrier that processed the shipment |
| `data.tracking_id` | string | Tracking/AWB number |
| `data.docs` | object | Map `document name → { url, base64 }`. The keys are the ones in the table above |
| `data.docs.*.url` | string | URL for direct download of the file |
| `data.docs.*.base64` | string | Content in Base64. Present only when `base64=true` |
| `data.embedded_docs` | array | Embedded documents. `null`/absent when `embedded=false` or without permission |
| `data.embedded_docs[].type` | string | `pdf` or `zpl` |
| `data.embedded_docs[].base64` | string | Content in Base64 |
| `data.attachments` | array | Attachments you sent. `null`/absent when `attachments=false` |
| `data.attachments[].id` | integer | **Attachment ID.** Use it to remove the attachment in `DELETE /v1/shipping/{shipping}/docs` |
| `data.attachments[].type` | string | `pdf`, `xml`, `jpeg` or `png` |
| `data.attachments[].description` | string | Description informed at creation |
| `data.attachments[].base64` | string | Content in Base64 |

## Printing labels

| Format | When to use it |
|---|---|
| `awb_pdf` | Regular printer (A4/Letter). Open the `url` or decode the `base64` |
| `awb_zpl` | Zebra thermal printer. Send the **raw** content (after decoding the Base64) straight to the printer queue |

> The ZPL content is text. Do not convert or reprocess it: send it exactly as it came after the decode.

## Managing attachments

| Operation | Route | Page |
|---|---|---|
| Send attachments at creation | `POST /v1/shipping` (`attachments` field) | [Shipment (v1)](api-remessa-v1.md) |
| Send attachments later | `PUT /v1/shipping/{shipping}` | [Shipment (v1)](api-remessa-v1.md#endpoint-update-shipment) |
| List attachments | `GET /v1/shipping/{shipping}/docs?attachments=true` | This page |
| Remove attachments | `DELETE /v1/shipping/{shipping}/docs` | [Shipment (v1)](api-remessa-v1.md#endpoint-remove-attachments) |

Attachment limits:

| Limit | Value |
|---|---|
| Accepted formats | `PDF`, `XML`, `JPEG`, `PNG` |
| Size per file | **5 MB** |
| Total request size | **90 MB** |

## Business rules
- The documents only exist **after** the processing at the carrier (`shipped` group in the tracking).
- `embedded_docs` depends on a **specific permission** in your account. Without it, the field is not returned,
  even with `embedded=true`. Related message:
  `Para obter os documentos incoporados a remessa precisa ter sido ao menos enviada.`
- If there is no document and no attachment, the response is `400` with
  `Nenhum documento encontrado com o código especificado!`.
- The `url` values point to external storage and may have an expiration. **Download and store** the files
  on your side if you need to keep them for a long time.
- The query by channel considers the `channel_identifier_number` informed in the **quotation**.
  Without `channel_code`, the search uses only the identifier.

## Common errors

| Status | Meaning | How to fix it |
|---|---|---|
| `400` | `Nenhum documento encontrado com o código especificado!` | Wait for the processing (`shipped` status) or check the identifier |
| `403` | No permission to query documents | Ask support for the permission |
| `404` | Shipment not found | Check `{shipping}` or the channel identifier |
| `422` | Non-numeric `channel_code` | Send an integer in `channel_code` |
| `500` | Unexpected error | Retry with backoff; if it persists, contact support |

## Final notes
- The query by `{shipping}` is the most direct and stable form.
- The query by channel is the best option when you want to work only with your order number.
- Combine `documents` + `base64=false` for fast responses in high-volume integrations.
