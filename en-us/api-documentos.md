# Shipment Documents

- [Back to the language README](README.md)
- Prerequisite: [Getting Started](api-primeiros-passos.md)

> ⚠️ **Examples are for illustration only:** all payloads, responses, identifiers, codes, documents and tokens
> on this page are fictitious and **are not valid data**. Replace them with the real data of your account and your operation.

## Overview
- Retrieves the documents generated by the platform and by the carrier after the shipment is processed:
  AWB (label), invoice, packing list, declaration and others.
- It also returns the **attachments** you sent when creating/updating the shipment.
- Each document comes with a `url` for download and, optionally, with the content in `base64`.
- Accounts with a specific permission also receive the **embedded documents** (all PDFs in a single file and all ZPL labels in a single content).
- Works for shipments created in **v1 and v2** (the documents routes exist only in v1).

## Base URL
- Production: `https://api.shipsmart.global`
- Staging: `https://hmlapi.shipsmart.com.br`
- Interactive documentation: `https://api.shipsmart.global/doc` and `https://hmlapi.shipsmart.com.br/doc`

## Authentication
```
Authorization: Bearer YOUR_TOKEN
lang: pt
```

| Header | Required | Values | Default | Note |
|---|---|---|---|---|
| `Authorization` | **yes** | `Bearer <token>` | - | Token of your account. The profile needs the shipment documents query permission |
| `lang` | no | `pt`, `en`, `es` | `pt` | Language of the messages |

## Usage flow
1. Create the shipment ([Shipment v1](api-remessa-v1.md) or [Shipment v2](api-remessa-v2.md)).
2. Query the [status](api-rastreio.md) until the shipment appears in the `shipped` group — that is when
   the documents start to exist.
3. Query the documents by `{shipping}` or by channel.
4. Download the file from the `url` **immediately** or decode the `base64`, and store it on your side.

> **Before `shipped`, the query may return `400 Nenhum documento encontrado com o código especificado!`.**
> This is expected: wait for the processing at the carrier. If the shipment has attachments, the response may be
> `200` bringing only the attachments (see [Business rules](#business-rules)).

## Key concepts

### Filterable document types (`documents`)

| Value in `documents` | Key in `data.docs` | Content |
|---|---|---|
| `awb_pdf` | `AWB` | Label/AWB in PDF |
| `awb_zpl` | `AWB_ZPL` and `AWB_ZPL_UPS` | Label/AWB in ZPL (thermal printer). For some carriers the key is `AWB_ZPL_UPS` |
| `awb_prc_pdf` | `AWBPRC` | AWB PRC label in PDF, issued for some carriers |
| `awb_prc_zpl` | `AWBPRCZPL` | AWB PRC label in ZPL |
| `awb_prc_fedex_pdf` | `AWBPRCFedex` | AWB PRC FedEx label in PDF |
| `awb_prc_fedex_zpl` | `AWBPRCFedexZPL` | AWB PRC FedEx label in ZPL |
| `invoice_pdf` | `Invoice` | Commercial Invoice in PDF |
| `packing_list_pdf` | `PackingList` | Packing list in PDF |
| `declaration_pdf` | `Declaration` | Content declaration in PDF |
| `non_dangerous_pdf` | `NonDangerousObject` | Non-hazardous goods declaration in PDF |

> **The `data.docs` keys have no spaces** (`PackingList`, `NonDangerousObject`, `AWBPRC`...), although the
> interactive documentation shows them with spaces (`Packing List`, `Non-Dangerous Object`, `AWB PRC`...).
> Program your reading based on the keys in this table.

Filter example:
```
?documents=invoice_pdf,awb_pdf,awb_zpl
```

> Not every document exists in every shipment: the set depends on the carrier, the destination country and the
> object type. Only the documents actually generated appear in `data.docs`, and each key appears
> **only once**.

### Embedded documents (`embedded_docs`)

| `type` | Content | Condition |
|---|---|---|
| `pdf` | All the returned PDF documents (after the `documents` filter) merged into a single PDF. The number of copies of each document and the inclusion of PDF attachments follow the embedding configuration of your account | The shipment must already have been processed at the carrier |
| `zpl` | All the returned ZPL labels (after the `documents` filter) concatenated, separated by a line break | At least one ZPL document must exist |

The embedded documents are only generated when **all** the conditions below are true:
`embedded=true`, `base64=true`, your account has the embedded documents permission and the shipment has
at least one returned document. Otherwise, `embedded_docs` comes as an empty list (`[]`).

### Printing labels

| Format | When to use |
|---|---|
| `awb_pdf` | Regular printer (A4/Letter). Open the `url` or decode the `base64` |
| `awb_zpl` | Zebra thermal printer. Send the **raw** content (after decoding the Base64) directly to the printer queue |

> The ZPL content is text. Do not convert or reprocess it: send it exactly as it came after decoding.

### Managing attachments

| Operation | Route | Page |
|---|---|---|
| Send attachments at creation | `POST /v1/shipping` (`attachments` field) | [Shipment (v1)](api-remessa-v1.md) |
| Send attachments later | `PUT /v1/shipping/{shipping}` | [Shipment (v1)](api-remessa-v1.md#endpoint-update-shipment) |
| List attachments | `GET /v1/shipping/{shipping}/docs?attachments=true&base64=true` | This page |
| Remove attachments | `DELETE /v1/shipping/{shipping}/docs` | [Shipment (v1)](api-remessa-v1.md#endpoint-remove-attachments) |

Attachment limits:

| Limit | Value |
|---|---|
| Accepted formats | `PDF`, `XML`, `JPEG`, `PNG` |
| Size per file | **5 MB** |
| Total request size | **90 MB** |

> Attachments **are only returned with `base64=true`**. With `base64=false`, `data.attachments` always comes empty.

## Endpoint: query documents by shipment

- **Method and route:** `GET /v1/shipping/{shipping}/docs`
- **When to use:** this is the most direct way. It accepts the quotation UUID, the AWB or the NF-e key.

### Parameters

| Name | Location | Type | Required | Size | Default | Description |
|---|---|---|---|---|---|---|
| `shipping` | path | string | **yes** | - | - | Shipment identifier. See the accepted forms below |
| `attachments` | query | boolean | no | - | `true` | Include the attachments sent by you. Only takes effect with `base64=true` |
| `embedded` | query | boolean | no | - | `true` | Include the embedded documents. Only takes effect with `base64=true` and with the specific permission |
| `base64` | query | boolean | no | - | `true` | Include the file content in Base64, in addition to the `url`. With `false`, attachments and embedded documents are not returned |
| `documents` | query | string | no | - | all | Comma-separated list of types (values from the [Filterable document types](#filterable-document-types-documents) table). Empty or absent: all |

Ways to inform `{shipping}` (use only one):

| Form | Value | How it is recognized | Notes |
|---|---|---|---|
| A | Quotation UUID | Contains a hyphen (`-`) | Recommended form |
| B | NF-e key | Exactly 44 numeric digits | Considers the most recent shipment with this key, disregarding cancelled shipments |
| C | AWB (tracking number) | Any other value | Only shipments created in the **last 90 days**; considers the most recent one with this AWB |

> Since any value with a hyphen is treated as a UUID, an AWB that contains `-` is not found by this route.
> In this case, use the quotation UUID.

Query parameter rules:

| Rule | Behavior |
|---|---|
| Boolean values | The following are considered true: `true`, `1`, `on`, `yes`. **Any other value, including empty** (`attachments=`), is considered `false` |
| `documents` with an unknown value | The value is ignored. If **no** value is valid, the filter is not applied and all documents are returned |
| `documents` with uppercase letters | Not recognized (the values are case-sensitive) |
| Repeated `documents` (`documents=a&documents=b`) | Only the **last** one is considered. Send all of them in a single parameter, separated by commas |
| `documents[]=...` | Not supported: the request fails with `500` |

> **Performance tip:** send `base64=false` when you are going to download from the `url`. The payload becomes much smaller
> and the response much faster. Remember that, in this case, attachments and embedded documents do not come in the response.

### Minimum payload

Endpoint without a body. The path parameter is enough (all query parameters take their default):

```
GET /v1/shipping/9c06fd75-d5f4-40eb-a1a8-f12086f49944/docs
```

### Maximum payload

```
GET /v1/shipping/9c06fd75-d5f4-40eb-a1a8-f12086f49944/docs?attachments=true&embedded=true&base64=true&documents=awb_pdf,awb_zpl,awb_prc_pdf,awb_prc_zpl,awb_prc_fedex_pdf,awb_prc_fedex_zpl,invoice_pdf,packing_list_pdf,declaration_pdf,non_dangerous_pdf
```

### Request example

```bash
curl --request GET \
  --url 'https://api.shipsmart.global/v1/shipping/9c06fd75-d5f4-40eb-a1a8-f12086f49944/docs?attachments=true&embedded=true&base64=true&documents=invoice_pdf,awb_pdf,awb_zpl' \
  --header 'Authorization: Bearer YOUR_TOKEN' \
  --header 'lang: pt'
```

Only the URLs, without Base64 content:

```bash
curl --request GET \
  --url 'https://api.shipsmart.global/v1/shipping/9c06fd75-d5f4-40eb-a1a8-f12086f49944/docs?base64=false' \
  --header 'Authorization: Bearer YOUR_TOKEN' \
  --header 'lang: pt'
```

### Response fields

| Field | Type | Presence | Description |
|---|---|---|---|
| `status` | string | always | `success`, `warning` or `error` |
| `message` | string | always | Message translated by the `lang` header |
| `data.docs` | object \| array | always | Map `document key → { url, base64 }`. The keys are those of the [Filterable document types](#filterable-document-types-documents) table. **When there are no documents, it comes as an empty list (`[]`)** |
| `data.docs.*.url` | string | always | URL to download the file. It may be temporary (see [Business rules](#business-rules)) |
| `data.docs.*.base64` | string \| null | always | Content in Base64. `null` when `base64=false` |
| `data.attachments` | array | always | Attachments sent by you. Empty list when `attachments=false`, `base64=false` or there are no attachments |
| `data.attachments[].id` | integer | - | **Attachment ID.** Use it to remove the attachment in `DELETE /v1/shipping/{shipping}/docs` |
| `data.attachments[].type` | string | - | File extension: `pdf`, `xml`, `jpg` or `png` |
| `data.attachments[].description` | string | - | Description informed when sending the attachment |
| `data.attachments[].base64` | string | - | Content in Base64 |
| `data.embedded_docs` | array | always | Embedded documents. Empty list when they do not apply (see [Embedded documents](#embedded-documents-embedded_docs)) |
| `data.embedded_docs[].type` | string | - | `pdf` or `zpl` |
| `data.embedded_docs[].base64` | string | - | Content in Base64 |
| `data.carrier` | string | when there are documents | Name of the contract that processed the shipment or, without a contract, the carrier name |
| `data.tracking_id` | string \| null | when there are documents | Tracking number/AWB |

## Endpoint: query documents by channel

- **Method and route:** `GET /v1/shipping/docs/{channel_identifier_number}/{channel_code}`
- **When to use:** when you only stored your own order number (informed in the quotation).

### Parameters

| Name | Location | Type | Required | Size | Default | Description |
|---|---|---|---|---|---|---|
| `channel_identifier_number` | path | string | **yes** | - | - | Order identifier in the channel, exactly as informed in the quotation |
| `channel_code` | path | integer | no | - | absent | Sales channel code informed in the quotation. It must be an integer |
| `attachments` | query | boolean | no | - | `true` | Same as [query documents by shipment](#endpoint-query-documents-by-shipment) |
| `embedded` | query | boolean | no | - | `true` | Same as [query documents by shipment](#endpoint-query-documents-by-shipment) |
| `base64` | query | boolean | no | - | `true` | Same as [query documents by shipment](#endpoint-query-documents-by-shipment) |
| `documents` | query | string | no | - | all | Same as [query documents by shipment](#endpoint-query-documents-by-shipment) |

> **How the search works:**
>
> - **With `channel_code`:** searches for the most recent quotation with this identifier **and** this channel code.
> - **Without `channel_code`:** searches for the most recent quotation with this identifier, **with or without** a channel code.
>   If you use the same identifier in different channels, always send the `channel_code`.
> - Unlike the [status query by channel](api-rastreio.md#endpoint-query-status-by-channel), this search
>   **also considers cancelled shipments**.
> - To omit the `channel_code`, simply do not send the segment. The value `,` is also treated as absent.

### Minimum payload

```
GET /v1/shipping/docs/PED-2026-0001
```

### Maximum payload

```
GET /v1/shipping/docs/PED-2026-0001/1?attachments=true&embedded=true&base64=true&documents=awb_pdf,awb_zpl,awb_prc_pdf,awb_prc_zpl,awb_prc_fedex_pdf,awb_prc_fedex_zpl,invoice_pdf,packing_list_pdf,declaration_pdf,non_dangerous_pdf
```

### Request example

```bash
curl --request GET \
  --url 'https://api.shipsmart.global/v1/shipping/docs/PED-2026-0001/1?base64=false' \
  --header 'Authorization: Bearer YOUR_TOKEN' \
  --header 'lang: pt'
```

## Business rules
- The documents only exist **after** processing at the carrier (`shipped` group in the tracking).
- **Response decision order:**

  | Documents found (after the filter) | Attachments (`attachments=true` and `base64=true`) | Response |
  |---|---|---|
  | Yes | Yes or no | `200` with `docs`, `attachments`, `embedded_docs`, `carrier` and `tracking_id` |
  | No | Yes | `200` with `docs: []`, `attachments` and `embedded_docs: []` (without `carrier` and `tracking_id`) |
  | No | No | `400` `Nenhum documento encontrado com o código especificado!` |

- The `documents` filter also applies to the decision above: if the filtered types do not exist yet and there are no
  attachments, the response is `400`.
- Documents whose file is not available are silently omitted. If none remain and there are no
  attachments, the response is `400`.
- `embedded_docs` depends on a **specific permission** in your account. Without it, the list comes empty, even with
  `embedded=true`.
- **URL validity:** when your account is configured to protect document links, each `url`
  is **temporary and valid for 5 minutes**. In other cases the link is public, but it may also be temporary.
  **Download and store** the files on your side right after the query; to download them again later, query the
  endpoint again.
- Only documents of shipments from your account are returned. Shipments from another account respond
  `400 Nenhum documento encontrado com o código especificado!` (by UUID and by channel) or
  `404 Esta remessa não foi encontrada!` (by AWB and by NF-e).
- The search by AWB considers only shipments created in the **last 90 days**.
- The search by NF-e key disregards cancelled shipments.

## Common errors

| Status | Meaning/Message | How to fix |
|---|---|---|
| `400` | `Nenhum documento encontrado com o código especificado!` | Wait for processing (status `shipped`), review the `documents` filter or check the identifier. In the query by channel, it also indicates that no shipment was found |
| `400` | `Remessa não encontrada!` — no shipment with the informed UUID (query by `{shipping}`) | Check the quotation UUID |
| `403` | `Has no permission!` | Ask support for the documents query permission |
| `403` | `Usuário especificado encontra-se bloqueado em nosso sistema!` | Account blocked: contact support |
| `404` | `Nenhum usuário encontrado para o token especificado!` | Check the token sent in `Authorization` |
| `404` | `Esta remessa não foi encontrada!` — AWB or NF-e key without a matching shipment in your account (AWB older than 90 days, NF-e of a cancelled shipment) | Check the AWB/NF-e or use the quotation UUID |
| `422` | `O campo channel code deve conter um número inteiro.` (in `data.channel_code`) | Send an integer in `channel_code` or omit the segment |
| `500` | `Oopss.. Algo inesperado aconteceu ao buscar documentos da remessa. Tente novamente mais tarde. Caso o erro persista, acione a equipe técnica!` | Retry with backoff; if it persists, contact support |

## Final notes
- The query by `{shipping}` with the quotation UUID is the most direct and stable way.
- The query by channel is the best option when you want to work only with your own order number.
- Combine `documents` + `base64=false` for fast responses in high-volume integrations.
- To find out when the documents become available, see [Shipment Tracking](api-rastreio.md).
- To send and remove attachments, see [Shipment (v1)](api-remessa-v1.md).
- Consolidated list of error messages: [Error Codes](api-codigos-de-erro.md).
